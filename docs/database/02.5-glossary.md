# Forensic Chain of Custody Management System (FCCMS)

# Domain Glossary

Version : 1.1

---

# Purpose

This document defines all business terms used throughout the FCCMS project.

Every document, database schema, API, frontend component, and backend service must use the terminology defined here.

The purpose of this glossary is to ensure consistency between developers, documentation, and AI-assisted code generation.

---

# A

## Account

A registered system user who has successfully completed activation and can authenticate into the application.

---

## Audit Log

A permanent append-only record of every user activity performed inside the system.

Audit Logs cannot be modified or deleted.

Example

- Login
- Create Evidence
- View Evidence
- Generate Report

---

# B

## Badge Number

Official Police Identification Number used to verify user identity before account activation.

Also referred to as Police ID.

---

## Business Rule

A mandatory rule that defines how the system must behave.

Business Rules cannot be violated.

---

# C

## Case

A criminal investigation handled by investigators and detectives.

A case contains one or more evidence items.

---

## Case Assignment

The relationship between users and cases.

Assignments determine which cases a user is allowed to access.

---

## Case Status

Current investigation stage of a case.

Possible values

- Open
- Under Investigation
- Pending Review
- Referred
- Suspended
- Cold
- On Hold
- Submitted to Prosecution
- In Court
- Archived

---

## Chain of Custody (CoC)

A chronological history showing who possessed evidence, when it was transferred, where it was transferred, and why.

This is the core feature of the FCCMS.

---

## Custodian

The current person responsible for an evidence item.

---

## Custody Event

A single event recorded within the Chain of Custody.

Examples

- CREATE
- VIEW
- HANDOVER_DISPATCH
- HANDOVER_ACK
- VERIFY

Custody Events are immutable.

---

# D

## Detective

A user responsible for reviewing investigations, approving evidence modifications, and supervising evidence integrity.

---

# E

## Evidence

A physical or digital item collected during an investigation.

Examples

- Laptop
- Mobile Phone
- USB Drive
- Knife
- Firearm
- Document

---

## Attachment

A file attached to an evidence item.

Examples

- Photo
- Video
- Audio
- PDF
- Laboratory Result

---

## Evidence Hash

A SHA-256 value generated to verify evidence integrity.

---

## Evidence Integrity

The condition where evidence has not been modified since registration.

Integrity is verified using SHA-256.

---

# F

## FLAGGED

Status assigned when a handover is not acknowledged within three calendar days.

Requires Superadmin review.

---

# H

## Hard Delete

Permanent removal of a record from the database.

Only allowed for Superadmin and only when no custody history exists.

---

## Hash Verification

The process of recalculating SHA-256 and comparing it with the stored value.

Verification occurs during

- View
- Edit
- QR Scan
- Report Generation

---

# I

## Investigator

A user responsible for creating cases, registering evidence, and performing evidence handovers.

---

# L

## Local Storage

Directory inside the application used to store uploaded evidence files.

Example

/uploads/evidence

---

# M

## MFA

Multi-Factor Authentication.

A second authentication factor required after entering username and password.

---

# O

## OTP

One-Time Password.

Used only during initial account activation.

Not used for daily login.

---

# P

## Police ID

Official identification number used to validate user identity before account activation.

Must be unique.

---

# Q

## QR Code

Encrypted QR code generated automatically for every evidence item.

The QR code stores encrypted information and can only be interpreted by the FCCMS application.

---

## QR View

Read-only QR operation.

Displays evidence information without changing ownership.

---

## QR Handover

QR operation used to transfer evidence ownership between authorized personnel.

Requires sender and recipient confirmation.

---

# R

## RBAC

Role-Based Access Control.

Determines what features a user can access based on their assigned role.

---

## Report

A generated summary of investigation or custody information.

Reports always perform hash verification before generation.

---

# S

## SHA-256

Cryptographic hashing algorithm used to verify evidence integrity.

---

## Soft Delete

Logical deletion where data remains in the database but is marked as deleted.

Used to preserve forensic history.

---

## Superadmin

Highest privilege user within the application.

Responsibilities include

- Create User
- Assign Personnel
- Resolve Flagged Handover
- Hard Delete (under strict conditions)

Superadmin cannot modify Audit Logs or Custody Events.

---

## System Log

Internal application event log.

Unlike Audit Logs, System Logs record application events.

Examples

- OTP Failure
- Database Error
- Hash Verification Failure
- Server Exception

---

# U

## User

Any authenticated person using FCCMS.

User roles include

- Superadmin
- Investigator
- Detective

---

# V

## Verification

The process of validating evidence integrity, user identity, or system security before allowing an operation.
