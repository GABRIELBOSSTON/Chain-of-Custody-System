Version : 1.0

# Purpose

This document describes the authentication and authorization workflow of the Forensic Chain of Custody Management System (FCCMS).

The authentication process ensures that only authorized police personnel can access the system through multiple layers of security.

The system uses:

- Email & Password
- OTP (Account Activation)
- MFA (Login Verification)
- JWT Authentication
- RBAC Authorization

---

# Authentication Overview

The authentication process consists of four stages:

1. Account Creation
2. Account Activation
3. Login Authentication
4. Authorization

# Stage 1 - Account Creation

Actor

- Superadmin

Description

The Superadmin creates a new user account.

Validation

- Police ID must be unique.
- Email must be unique.
- Role must exist.
- Password is hashed using bcrypt.

Result

The account is created in an inactive state.

---

# Stage 2 - Account Activation

Actor

- User

Description

The user activates the account using the OTP sent by the system.

Validation

- OTP must be valid.
- OTP must not expire.
- OTP can only be used once.

Success

- Account becomes active.

Failure

- Activation rejected.

---

# Stage 3 - Login

Actor

- User

Description

The user enters email and password.

Validation

- User exists.
- Account is active.
- Password matches bcrypt hash.

Failure

- Invalid credentials.

Success

- Continue to MFA verification.

---

# Stage 4 - MFA Verification

Actor

- User

Description

The user enters the MFA code generated by an authenticator application.

Validation

- Secret key exists.
- Code is valid.
- Code has not expired.

Failure

- Login rejected.

Success

- JWT Access Token is generated.

---

# Stage 5 - Authorization

After successful login, every request must include a valid JWT.

The backend validates:

- JWT Signature
- Token Expiration
- User Status
- User Role

Only authorized users may access protected resources.

# Authentication Components

Password

Algorithm

- bcrypt

Purpose

Protect user passwords.

---

OTP

Purpose

Activate newly created accounts.

Usage

One-time only.

---

MFA

Purpose

Provide a second authentication factor.

Implementation

Time-Based One-Time Password (TOTP).

---

JWT

Purpose

Authenticate API requests.

Header

Authorization: Bearer <token>

---

RBAC

Purpose

Restrict system features based on user role.

Roles

- Superadmin
- Investigator
- Detective

---

# Authentication Rules

- Superadmin creates all user accounts.
- Users cannot register themselves.
- Passwords are never stored in plaintext.
- OTP is required only for account activation.
- MFA is required for every login.
- JWT is required for protected APIs.
- Inactive accounts cannot log in.
- Deleted users cannot log in.

# Authentication Failure Scenarios

Invalid Email

Result

Login rejected.

---

Wrong Password

Result

Login rejected.

---

Expired OTP

Result

Activation rejected.

---

Invalid MFA Code

Result

Login rejected.

---

Expired JWT

Result

User must log in again.

---

Inactive Account

Result

Access denied.
